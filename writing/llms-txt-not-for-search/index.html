llms.txt: Not for Search, for the Models

The file is not a ranking trick. It is a small act of editorial judgment for machines that need a map.

Primary keyword: llms.txt best practices 2026
Type: Spoke
Status: Drafted

The finding

llms.txt does not improve your Google ranking. Google has said so. Treating it as an SEO shortcut is a category error.

Its more useful job is quieter. It gives a language model a short, curated explanation of a website and points to the pages that deserve attention. That makes it a context layer. Not a control panel.

The distinction matters because AI visibility is not one system. Search crawlers, retrieval systems, training pipelines, browsing agents, and answer engines make different choices. One file cannot command all of them. It can still make the right source easier to understand.

Definition

llms.txt

A proposed Markdown file at a website's root that gives language models a concise description of the site and links to its most useful, authoritative pages.

The proposal came from Answer.AI's llms-txt specification. It is intentionally simple. A heading. A short explanation. Curated links. No elaborate permission system. No promise that a model must obey it.

That simplicity is its strength and its limit. Signal Architecture is the wider system that makes an entity legible. llms.txt is one signpost inside that system.

What the file can do

JobWhat it helps withWhat it cannot promise
OrientationExplains what the site is about before a model reads deeply.It cannot force a model to read the site.
SelectionIdentifies canonical pages and preferred sources.It cannot force a citation or recommendation.
CompressionOffers a clean starting point when a full site is too large.It cannot replace the pages it links to.
MaintenanceCreates a visible inventory of what the publisher considers important.It cannot repair stale, contradictory site content.

Think of it as a table of contents written for a visitor who reads in tokens. The table of contents is useful. It is not the book.

The Google boundary

Google's documentation for AI features in Search says there are no additional technical requirements or special markup that guarantees inclusion. Google has also stated that llms.txt has no effect on Search.

That is not a reason to delete the file. It is a reason to put it in the correct layer. Use standard crawlable architecture for Search. Use clear entity definitions, citations, and structured data for retrieval. Use llms.txt as a curated handoff for model-readable context.

Search Engine Land's overview of the proposal captures the current state accurately: llms.txt is a proposed standard, not an established protocol adopted uniformly by major model providers.

llms.txt best practices

  1. Put it at the root. Use https://example.com/llms.txt. Keep the path obvious and stable.
  2. Write the opening like a briefing. State who owns the site, what it covers, and why the material is authoritative. Three to five sentences is enough.
  3. Link to canonical pages. Prefer original research, definitions, documentation, and evidence. Do not turn the file into a dump of every URL.
  4. Use headings. Separate core concepts, research, case studies, and supporting material. A model should understand the hierarchy without guessing.
  5. Keep descriptions factual. Say what a page contains. Do not write claims such as “the world's leading guide” unless the evidence is on the page.
  6. Update it when the site changes. A stale map is worse than no map. Remove dead links and pages that no longer represent the entity.

Our own llms.txt file follows this pattern. It points to the canonical GEO definitions, the ARM Framework, and the original Signal Architecture glossary.

The model-readiness ladder

Publishing the file is the first rung, not the finish line. A useful audit asks four questions.

LevelQuestionEvidence
1. PresentDoes the file exist at the root?HTTP 200 response and valid Markdown.
2. CoherentCan a stranger understand the site from it?Clear description and organized sections.
3. VerifiableDo the links support the claims?Canonical pages, dated research, consistent entity details.
4. MaintainedDoes the file stay aligned with the site?Regular review, working links, current terminology.

This is the Model-Readiness Ladder. It is a practical distinction between having a file and having a useful one. Most audits stop at Level 1 because a URL is easy to check. Models need Level 3 and Level 4.

That is where Entity Authority enters. A curated file cannot create recognition by itself. It can reinforce a consistent identity that already exists across the site, citations, and external references.

What to measure

Do not claim that llms.txt increased citations unless you can isolate the change. The current public evidence is mixed. Ahrefs' analysis of 137,000 sites found widespread non-use and limited evidence that the file alone changes visibility. That is a useful warning against magical thinking.

Measure the surrounding system instead:

  • Does the file return a clean response?
  • Are the linked pages canonical, current, and consistent?
  • Do probe queries produce more accurate entity descriptions over time?
  • Are citations pointing to the pages named in the file?

Share of Model is the outcome to watch. llms.txt is only one input into that result. If the underlying pages are thin or contradictory, the map will not rescue the territory.

The conclusion

Publish llms.txt if you can maintain it. It is cheap, legible, and useful as a small editorial signal.

Do not publish it instead of good site architecture. Do not describe it as a ranking factor. Do not promise that it makes ChatGPT, Claude, Gemini, or Perplexity cite you.

The sober position is the durable one. llms.txt is not for Search. It is for giving models a better first read.
