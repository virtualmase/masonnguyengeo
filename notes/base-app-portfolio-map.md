# Base App Portfolio Map

## Assessment boundary

This map evaluates what each supplied URL visibly presents in its public state. It does not verify source ownership, live data provenance, commercial customers, compliance certifications, or performance claims. Any public-site use should describe these as **builds, prototypes, experiments, or public system studies** unless a source repository, live data record, or independently verifiable deployment supports stronger language.

## Integration standard

A Build Record should use the same evidence-first discipline as the research pages. Every record needs a plain description of the build, a defined role, a public link or source link, its current phase, what was personally implemented, and a claim boundary. It should never borrow customer logos, performance numbers, investment language, compliance labels, or partner names as proof if the underlying record is not independently available.

> **Recommended framing:** “Selected applied systems built in public or maintained as prototypes. Each record identifies its current phase and does not imply customer adoption, platform endorsement, or performance beyond the available evidence.”
